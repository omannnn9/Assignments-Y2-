Hyperledger Fabric addresses these concerns. Each organisation has a digital ID and gets checked through the Membership Service Providers (MSPs). This helps UoM ensure that only approved institutions can participate in the network (Hyperledger Foundation, 2020).

For UoM, a consortium would be more practical, since no university should trust the others blindly. UoM, the University of Technology, Mauritius (UTM) and the Open University of Mauritius could each run their own node. Instead of one organisation holding all power, they all agree on how credentials get verified across the three institutions. This is exactly what Fabric's endorsement policies enforce, which helps to decide which organisations should approve transactions (Hyperledger Foundation, 2020). 

Fabric allows organisations to control access to data using channels or private data collections (Hyperledger Foundation, 2020). This backs the idea of keeping students’ personal details off-chain while only the SHA-256 hash is on-chain for verification. However, to effectively use Fabric, UoM and its consortium partners would basically need to provide or manage the required infrastructure, security and regular maintenance work. This means that the university will have ongoing costs, unlike relying on an existing public network. Even though it is harder to manage, the consortium has more control over the system and its operations. Furthermore, employers can check credentials using a simple verification service without even needing to join the consortium.

Therefore, the recommended architecture is a permissioned consortium blockchain using Hyperledger Fabric. Only a hash is stored on-chain. This can help reduce the conflict between blockchain immutability and the DPA 2017 (Data Protection Act, 2017). The trade-off is that UoM loses on an easy global access public chains offer. Still, this data is sensitive, thus it is better to protect confidentiality or not depend on unpredictable gas fees.
